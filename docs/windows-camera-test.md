# Windows 相机采集测试步骤

适用于 DeepMirror Windows x64 测试版和当前检查到的 Insight 7 相机（固件 2.1.2、VID/PID `3652:0104`）。Windows 编译、离线测试和打包自检已通过；以下步骤用于实际相机联机验收。

## 1. 准备程序与连接

1. 登录 GitHub，下载 [Windows 测试程序](https://github.com/q1234ew/deepMirror/releases/download/windows-build-3/DeepMirror-Windows-x64.zip)。[版本与校验文件](https://github.com/q1234ew/deepMirror/releases/tag/windows-build-3)位于私有仓库，需使用有访问权限的账号。
2. **完整解压**到本地目录，例如 `D:\DeepMirror`。不要直接在压缩包内运行，也不要单独移动 EXE，旁边的 DLL 和插件目录都要保留。
3. 用支持 USB 3 数据传输的线连接相机，优先直连电脑的 USB 3 接口。
4. 确认相机处于 **UVC 模式**，顶部开关显示红色。切换模式后等待约 45 秒。
5. 关闭可能占用相机的 Viewer、视频会议等程序。在 Windows“设置 → 隐私和安全性 → 相机”中，允许桌面应用访问相机。

## 2. 开启深度输出

1. 在连接相机的 Windows 电脑上打开：
   - 优先：[http://looper.local](http://looper.local)
   - 域名无法访问时：[http://169.254.10.1](http://169.254.10.1)
2. 展开 **System** 菜单，找到包含以下控件的设备控制页：
   - `Device Sleep/Wakeup`
   - `Enable Depth Stream`
3. 确认设备处于唤醒状态，将 **Enable Depth Stream** 开启。
4. 等待页面操作完成，确认开关保持开启，再启动采集程序。

此前检查时，这台相机的深度开关为关闭状态。采集程序不会自动开启深度。

## 3. 选择真实设备并启动

1. 运行 `deepmirror.exe`。
2. 在右侧“数据源”选择 **Insight 相机 / Windows SDK**。
3. 将保存目录设为可写位置，例如 `D:\DeepMirrorCaptures`。
4. 首次测试将预览目标帧率保持为 **15 FPS**，连续保存间隔保持为 **1000 ms**。
5. 点击“启动采集”，展开底部“日志”，观察初始化和采集状态。

启动后，程序读取标定并等待有效 RGB-D 配对。**目前只有收到有效配对后，才会更新三路预览。**因此，缺少深度或标定读取失败时，也可能看不到 RGB 预览。

## 4. 验证三路预览

| 预览 | 检查方法 | 预期结果 |
|---|---|---|
| RGB | 面向有纹理、光线充足的场景，缓慢移动物体 | 画面持续更新、颜色正常；当前设备预期为 1088×1920 竖幅 |
| 深度 | 在约 0.5～2 米处放置纸箱、书本等不透明物体，前后移动 | 物体轮廓可辨认，随距离变化呈现不同颜色；部分无效区域可为黑色 |
| 彩色点云 | 拖动旋转、滚轮缩放，双击复位 | 能看出物体与背景的空间层次，点云颜色与物体大致对应 |

同时检查底部状态：

- 帧序号持续增加。
- 有效点数大于 0。
- 数据源标记为“真实设备”。
- 显示“主机到达时间”配对，而非“模拟”。

配对阈值为 **20,000 μs（20 ms）**。这是两路回调到达电脑的时间差，不等于曝光同步误差。右侧目标帧率只限制界面刷新，不修改相机帧率。

## 5. 验证单次保存

1. 将场景保持静止，点击“保存当前组”。
2. 等待日志出现保存成功，打开保存目录中新生成的文件夹。
3. 确认包含以下文件：

| 文件 | 检查内容 |
|---|---|
| `rgb.png` | 能打开，内容与采集场景一致 |
| `depth_mm.png` | 原始 16 位深度，单位毫米；普通图片查看器显示异常明暗不代表损坏 |
| `depth_preview.png` | 可直接查看的深度伪彩色图 |
| `cloud.ply` | 彩色点云，单位米；可用支持 PLY 的点云工具独立检查 |
| `metadata.json` | 时间戳、尺寸、标定和配对信息 |

重点检查 `metadata.json`：

- `source` 应为 **`windows_sdk`**，不能是 `simulation`。
- `pairing_clock` 应为 `host_monotonic_callback_arrival`。
- `points` 应大于 0。
- `pair_delta_us` 的绝对值应不超过 20,000。
- 应包含 `left_calibration` 和 `rgb_calibration`。
- 当前设备预期有效深度尺寸为 **544×640**；最终以实际标定和记录为准。

## 6. 验证连续保存与停止

1. 点击“开始连续保存”，运行约 10 秒。
2. 点击“停止连续保存”，确认目录中生成多组完整文件。
3. 比较首尾几组 RGB 和深度预览，确认内容有更新。
4. 点击“暂停采集”，确认帧序号停止变化、界面仍可操作。

连续保存采用间隔抽样；写盘繁忙时会跳过请求，因此不保证每秒一定生成一组，也不是全帧录像。

## 7. 常见问题

| 现象 | 优先排查 |
|---|---|
| 配置网页打不开 | USB 数据线、启动等待、虚拟网卡；尝试直接访问设备 IP |
| 没有真实设备选项 | 是否下载了 Windows 构建包，是否运行了正确 EXE |
| 超过 3 秒无有效配对 | 深度开关、UVC 模式、USB 连接、其他程序占用 |
| 标定读取失败或尺寸不匹配 | 保留日志；程序会拒绝猜测标定，不要据此判断相机硬件损坏 |
| 点云有形状但颜色明显错位 | 静止场景重新检查；保留完整数据组，进一步核对标定、去畸变状态和时间配对 |
| 保存失败 | 目录写权限、剩余磁盘空间、日志错误信息 |

本轮验收目标是：**真实模式下三路预览持续更新，单次和连续保存成功，文件来源及格式正确。**精确测距、颜色对齐精度和长时间稳定性还需要进一步测试。

发生问题时，请保留程序日志、完整的一组输出文件和现象描述。分享数据前检查 RGB 中是否包含个人或业务信息。

如果初始化时提示“标定读取失败”，点击底部“打开 SDK 日志目录”，保留本次运行的 `sdk-*.log`，并记录左目和 RGB 的返回值。新版会遍历设备的视频控制接口与扩展节点，尝试读取实际标定；日志包含接口路径、节点和底层错误码。没有读到有效标定时会停止真实采集，避免生成错误的彩色点云。日志文件在每次启动时新建，其路径也会显示在程序日志中。

如果 SDK 日志显示 `RGB=(absent)`、`Composite=(absent)` 或候选接口数量为 0，点击右侧数据源下方的“设备诊断…”。窗口显示当前 SDK 的筛选条件、Windows 设备名称、硬件 ID、实例 ID、驱动服务和问题代码，以及未经厂商筛选的 DirectShow 视频输入列表。插拔或切换模式后点击“刷新设备”，再点击“复制诊断信息”分享结果。此功能不依赖 SDK 初始化成功，也不需要运行 PowerShell；它只读取设备信息，不修改驱动或配置。Mac 版会提示此诊断需要在 Windows 上运行，模拟采集不受影响。
